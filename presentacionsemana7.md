En nuestra clase de hoy vamos a dar un paso crucial en el desarrollo web profesional: conectar nuestra interfaz estática en Vue 3 con un servidor real construido en Node y Express. Actualmente en nuestro proyecto ERP contable tenemos los clientes y movimientos escritos en arreglos dentro del código. Si presionamos F5, todo se borra. Hoy solucionaremos eso separando interfaz de persistencia.
"Minuto 1:15 - 3:00 | Arquitectura, APIs y REST (Diapositivas 3, 4 y 5):"Para esto dividiremos nuestra arquitectura en dos proyectos independientes: el frontend en el puerto 5173 y el backend en el puerto 3000. La API actúa como nuestro contrato formal. Usaremos la filosofía REST, lo que significa que nuestras URLs representarán recursos en plural como /api/contactos o /api/movimientos, y no verbos de acción."Minuto 3:00 - 5:00 | Protocolo HTTP, JSON y Express (Diapositivas 6, 7 y 8):"Los verbos los aporta el protocolo HTTP: GET para leer, POST para crear, PUT para actualizar y DELETE para eliminar. Toda la comunicación viajará en formato JSON acompañada de un código de estado, por ejemplo 200 OK o 201 Created. En nuestro servidor Express activaremos CORS para permitir la comunicación entre puertos y usaremos express.json() para parsear los datos recibidos.
"Minuto 5:00 - 7:00 | Asincronismo y Control de Errores (Diapositivas 9 y 10):"Debido a que las consultas de red toman tiempo, trabajaremos de forma asíncrona mediante Promesas y la sintaxis async/await. Es muy importante recordar que await no congela el navegador. Además, con fetch debemos verificar explícitamente respuesta.ok dentro de bloques try/catch/finally para gestionar estados de carga y error."Minuto 7:00 - 9:00 | Fetch vs Axios y Reactividad Vue (Diapositivas 11, 12 y 13):"Podemos consumir la API usando fetch nativo o mediante la librería Axios, la cual nos permite configurar una baseURL centralizada. Cuando los datos llegan al cliente, al asignarlos a nuestro ref de Vue dentro de onMounted(), el sistema de reactividad actualiza automáticamente la tabla sin tocar manualmente el DOM.
"Minuto 9:00 - 11:30 | Pruebas, Caso Real y Cierre (Diapositivas 14 y 15):"Antes de integrar el frontend, siempre probamos nuestros endpoints de forma aislada en Postman o Insomnia. Al crear un movimiento contable, el flujo recorre desde el formulario Vuetify hasta la validación en Express, respondiendo un 201 y actualizando el balance general.
